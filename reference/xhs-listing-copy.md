`reference/promo-qr-research.md`（二维码与归因）。

## 一、名称

平台对组件名的字数上限没有公开说明，按「6~10 字、含品类词」准备，按优先级取用：

| 顺序 | 名称 | 说明 |
| --- | --- | --- |
| 1 | 附近停车月卡 | 品类词 + 位置，最贴近用户搜索词，工具属性强 |
| 2 | 泊月停车月卡 | 带品牌，适合已通过后长期挂载 |
| 3 | 停车月卡查询 | 最「工具」、最不像广告，被拒时的保守选择 |

不要用「最省」「最低价」「优惠」进名称——绝对化用语和价格承诺都是审核敏感点。

## 四、详细介绍（正式版，按 500 字内写）

```
【能做什么】
· 按当前位置或手动选城市，看附近哪些车场有停车月卡
· 按月卡 / 季卡 / 夜间包月、业态、区域筛选，按价格或距离排序
· 点开套餐看价格、原价、停放时段与规则摘要
· 点「扫码办卡」生成该套餐的二维码，保存到相册后在微信扫一扫打开官方小程序办理

【数据从哪来】
车场与套餐信息采集自停车服务商公开发布的在售数据，按日生成离线快照打进工具内
（本工具为离线包，不联网、不请求接口），因此数据有滞后，页脚标注更新日期。

【关于办理】
本工具只做查询与展示，不代收款、不提供交易功能。办理、支付、开票全部在官方小程序内完成，
价格与规则以官方页面为准。

【定位权限】
仅用于按当前位置推荐最近的车场（首次使用时询问授权）。位置只在本机参与距离计算，
不上传、不存储。拒绝授权仍可手动选城市和使用其余功能。
```

## 六、上传流程（清单）

1. 小红书 App / 创作服务平台登录自己的号（无需开发者账号、无需企业资质）；
2. 创作服务平台 → Builder Hub → 小工具 → 上传 zip；
3. 包用 `minitool/dist/zhao-tingche-minitool.zip`（首审就是 `--max-parks 3` 那个 32KB 的）；
4. 填名称、简介（用第二节的首审版）、封面（先试 `cover-1x1.png`，上传页若报比例再换）；
5. 真机预览走一遍：定位 → 筛选 → 点套餐 → 保存二维码 → 相册里能看到图；
6. 提交审核，**记下提交时间**（后面判断「审核超时」要靠它）；
7. 通过后在发布页「添加组件」挂到笔记（老笔记可编辑追加）。

## 七、被问到时的回答（提前想好）

| 问题 | 回答 |
| --- | --- |
| 二维码跳转站外，是否导流？ | 二维码是车场官方套餐的分享链接，由官方小程序生成，扫码后进入的是官方小程序办理页；工具本身不代收款、不做交易，只做信息展示。 |
| 链接里带的 shareCode 是什么？ | 是官方小程序的分享来源参数（服务商侧的来源统计），不是自建跳转、不是外链网页。 |
| 数据来源是否授权？ | 采集自服务商公开发布的在售套餐信息，仅做展示与检索，不存储用户数据；页脚注明数据更新日期与「以官方页为准」。 |
| 为什么不联网实时查？ | 容器不允许联网，按官方静态资源规范把数据打包为离线快照，每日更新一版。 |

## 八、风险与判断

- 二维码引导去微信扫码是**唯一可能被拒的点**，其余（离线包、无联网、无用户数据）都符合容器规范。
- 若首审被拒且理由是「站外导流」：下一版去掉「保存二维码」按钮，只保留查询与「到官方平台搜索该车场」的文字指引，
  工具价值下降但可保住上架；这条路的改造量约半天。
- 若首审被拒理由是「数据/资质」：需要服务商侧的授权说明，短期内做不了，先放弃这条渠道。
- 审核时长官方没承诺，按 1~3 个工作日预期；超过 5 个工作日可以走平台反馈问进度。
